# Evidence Path Contract — Baum-OS v0.1

> CANONICAL · DOCS-ONLY · NO RUNTIME IMPLEMENTATION

## Purpose

Defines where Evidence for Baum-OS agent runs lives, what minimal structure a run folder must have, and what counts (or does not count) as Evidence. This document is the single anchor for the `pi.tier1.evidence_audit` skill before it is authored.

No runtime is activated by this document. No provider is called. No schema is changed. No Vault is written.

## Canonical Evidence Path

```
sandbox/runs/<timestamp>/
```

`<timestamp>` is a UTC ISO-8601 compact string, format: `YYYYMMDDTHHMMSSz`
Example: `sandbox/runs/20260623T225209Z/`

**Decision basis:** This path is already established through live use (two run folders exist as of 2026-06-23) and is explicitly mandated in `docs/pi-tier-1-draft-workflow.md` § Evidence & Storage. It is not a new definition — this document formalizes what is already canonical.

Alternative paths require a separate owner-approved schema-change slice before use.

## Minimal Run Folder Structure

A run folder is valid Evidence if it contains at least these files:

| File | Required | Content |
|------|----------|---------|
| `intent.md` | yes | What the run was supposed to do, scope, approved skill contract |
| `commands-run.md` | yes | Commands executed (no secrets) |
| `files-read.md` | yes | Files read, or the word `none` |
| `files-changed.md` | yes | Files changed, or the word `none` |
| `validation.md` | yes | Checks executed and pass/fail results |
| `diff.patch` | yes | Git diff output, or empty if no changes |
| `risks.md` | yes | Real open gaps, or the word `none` |
| `next-gate.md` | yes | One concrete next slice |

The full field set (run metadata, secret check block, decision verdict) is defined in `sandbox/runs/run-evidence-template.md`, which is the authoritative template. This contract does not supersede that template — it anchors the path and minimum file set.

## What Counts as Evidence

- Markdown files under `sandbox/runs/<timestamp>/` that are present, non-empty, and traceable to a real run
- `diff.patch` generated by `git diff` at the time of the run (may be empty for read-only runs)
- Validation output captured verbatim (pass or fail)
- Secret-check block confirming no `.env` read, no API keys exposed, no auth files accessed

## What Is Explicitly Not Evidence

- Files outside `sandbox/runs/<timestamp>/`
- Retrospective reconstruction of a run that did not happen
- Vault content or Vault references
- Provider API responses not captured locally during the run
- Output from commands that were not actually executed in this slice
- Any file containing real secrets, keys, tokens, or credentials

## Hard Boundaries

```
read-only / draft-only:
  Evidence files are written once per run, then read-only.
  No post-hoc mutation of evidence to fix a failed run.

no Vault writes:
  Evidence stays in sandbox/runs/<timestamp>/.
  No evidence artifacts go to Vault.

no Pi execution:
  This document does not trigger Pi. Pi runs are separate owner-approved slices.

no provider calls:
  No LLM API is called to produce this document or any evidence file.

no schema changes:
  Adding or removing required files from the minimal structure requires a
  separate owner-approved schema-change slice.

no secrets:
  No .env, no printenv, no API keys, no credentials in any evidence file.
```

## Relation to `pi.tier1.evidence_audit`

The `pi.tier1.evidence_audit` skill will consume Evidence produced under this contract. Its scope:

- Verify that a run folder under `sandbox/runs/<timestamp>/` is complete per the minimal structure above
- Verify the secret-check block is present and negative
- Verify that `validation.md` contains an explicit pass or fail verdict
- Verify that `diff.patch` is consistent with `files-changed.md`
- Produce an audit result: `pass | rework | blocked`

This contract is a prerequisite for that skill. The audit skill must not be authored before this contract is merged.
