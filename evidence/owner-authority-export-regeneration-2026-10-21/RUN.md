## Rules enforced (all fail closed)

| Rule | Statement |
| --- | --- |
| A1 | The trust anchor is a governed surface, read from the pinned canonical location and validated against its contract. |
| A2 | An anchor that publishes no key authorizes nothing (`OWNER_AUTHORITY_NOT_PUBLISHED`). |
| A3 | The signing key must be published, active and hold the `canonical_owner` role (`OWNER_AUTHORITY_KEY_UNKNOWN`, `OWNER_AUTHORITY_KEY_REVOKED`). |
| A4 | The signature must verify over the canonical body of the approval (`OWNER_APPROVAL_SIGNATURE_INVALID`). A tampered body does not verify. |
| A5 | The approval must name the exact promoted skill and the exact candidate content (`OWNER_APPROVAL_SKILL_MISMATCH`, `OWNER_APPROVAL_CANDIDATE_MISMATCH`). |
| A6 | The approval artifact must live in the canonical decision surface `core/authority/approvals/` of the target tree (`OWNER_APPROVAL_PATH_ESCAPE`). |
| A7 | A decision expires: an approval older than the bound cannot authorize a promotion (`OWNER_APPROVAL_STALE`). A decision dated in the future is refused (`OWNER_APPROVAL_FUTURE`). |
| E1 | The registry and every provider export are regenerated from the canonical tree by the canonical generators (no second implementation). |
| E2 | Every written export is read back and compared with the digest of the content that was written. |
| E3 | The regenerated registry must contain the adopted skill — an export that does not reflect the adoption is an incomplete regeneration. |
| E4 | The regeneration is bound to the adoption: the record names the adoption digest, the generator version and the digest of every written export. |
| R1 | A failed promotion leaves **no** mutation behind: the canonical file and every export surface are restored, each independently; a restore that fails is reported as a named failure (`PROMOTION_ROLLBACK_FAILED`) instead of silently leaving a half-applied adoption. |

## The trust anchor is not caller input

- The **library** default points at the canonical location of the installation; the parameter exists as a documented test seam.
- The **CLI** accepts an allowlist of inputs. Neither the trust anchor nor the evidence age bound is part of it: an input file cannot point the promotion at an anchor the caller controls, and it cannot widen the freshness bound of the behavioral evidence.
- The adoption record names **which** anchor vouched for the approval (`owner_approval.authority_digest`), so the decision is reconstructable.
